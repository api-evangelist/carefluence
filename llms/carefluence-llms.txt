# Carefluence

> Carefluence is a health-IT interoperability vendor whose product is an
> ONC-certified, FHIR-based Open API platform. Its Carefluence Open API R4 was
> certified 2022-06-29 under CHPL ID 15.04.04.2657.Care.R4.01.0.220629 for the
> § 170.315(g)(10) Standardized API for Patient and Population Services
> criterion, and Carefluence says it was the first FHIR-based Open API product
> to earn ONC 2015 Edition certification, in July 2016. EHR, telehealth, remote
> monitoring and HIE vendors license the platform to reach compliance and to
> exchange data with other systems.

This file was generated by API Evangelist from artifacts fetched from
Carefluence's own public surface on 2026-09-02. Carefluence does not publish an
llms.txt (https://carefluence.com/llms.txt returns 404).

## The API

- [Carefluence Open API R4 documentation](https://api.carefluence.com/): the
  provider's public Postman documentation and collection — 104 requests across
  38 folders, with USCDI element tables per FHIR resource.
- FHIR R4 service base: `https://classic.carefluence.com/r4/`
  (`https://fhir.carefluence.com/r4/` serves the identical contract).
- [CapabilityStatement](https://classic.carefluence.com/r4/metadata): anonymous,
  FHIR 4.0.1, 24 resource types, US Core IG v3.1.1 profiles, bulk-data
  group-export declared on Group.
- [SMART configuration](https://classic.carefluence.com/r4/.well-known/smart-configuration):
  13 SMART App Launch capabilities including launch-ehr, launch-standalone and
  permission-offline.
- Authorization server: `https://core.carefluence.com/cf.admin.core`
  ([OpenID discovery](https://core.carefluence.com/cf.admin.core/.well-known/openid-configuration),
  51 distinct SMART scopes, PKCE S256, RS256 id tokens).

## Getting access

## What is NOT published

An agent should not go looking for these — they were probed on 2026-09-02 and do
not exist:

- No OpenAPI or Swagger document. Despite the product being named "OpenAPI",
  "OpenAPI" here means "open API"; the machine-readable contract is the FHIR
  CapabilityStatement.
- No AsyncAPI document, despite FHIRops being described as AsyncAPI-based.
- No reachable MCP server: the product page publishes no endpoint, no install
  command and no package.
- No A2A agent card at /.well-known/agent-card.json or /.well-known/agent.json on
  any host.
- No security.txt, no /.well-known/api-catalog, no trust center, no status page,
  no changelog, no published rate limits, no priced plans.
- `docs.carefluence.com` is a dangling CNAME to SwaggerHub's ingress and serves
  nothing (Cloudflare error 1001 / TLS handshake failure).
